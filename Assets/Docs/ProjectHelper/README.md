# ProjectHelper · V3 语言设计

独立于 Unity 的设计文档编辑器。入口仍为 `http://127.0.0.1:4317/`，双击本目录的 `启动工作台.cmd` 即可使用；关闭服务用 `停止工作台.cmd`。需要 Node.js 20+，本机使用 Node 24。工具只读游戏来源资产，不修改 SO、场景或运行时规则。

## 四个主界面

| 界面 | 编写内容 |
| --- | --- |
| 词库 | 添加／移除词，上传／替换／清除符号，编辑多个词义及其词性。没有图片时符号留空；中文词义不是符号。子页管理词性与 SO 对照。 |
| 语法结构 | 点选或拖拽任意词性、指定词义构成有序槽位；在“规则说明”中自由描述共同规则、适用条件与表现，另填撤销后怎样及备注。共同条件说明按需展开，用文字描述，不再填写位置编号。查看单句仍留在语法内，有返回列表按钮。 |
| 所有可能性 | 按句子编号、词义、语法和审核状态筛选；查看继承逻辑，填写长备注及单句特殊效果；用多个句子编号记录共存、冲突、顺序和额外效果。 |
| 开发进度 | 从词、词性、语法或句子提交事项，按版本和进度统一查看、处理及验收。开发进度属于提交事项，不逐句维护。 |

“词性槽位”匹配该词性的任意有效词义；“指定词义槽位”只匹配那个含义。例如名词＋指定的移动＋名词。不同槽位可使用同词；需要限制时直接在备注中说明，并提交开发事项。文字条件不会自动改变枚举；此前保存的结构约束仍有效并以文字显示，不再提供位置选择器。词性名称和归类都可修改，“化词”只是初始分类，不是固定游戏规则。

## 提交与验收

在来源页面点“提交开发事项”，填写要做什么和所属版本，再点“提交并保存”。此操作会一并保存当前设计。事项使用永久 `D-0001` 编号；同来源、同版本的未完成需求合并更新，已通过后的新需求另建事项。提交仅登记待办，不自动执行游戏开发。

进度为待处理、开发中、待你验收、已通过、需要修改、暂不处理。开发完成后由代理填写完成内容和验证结果，标为“待你验收”；只有用户明确验收通过后才标“已通过”，代理不能因自己测试通过而代替用户验收。“需要修改”要求填写反馈。

每次提交保存相关设计快照和处理记录。来源设计变化后提示核对，并阻止直接按旧设计提交验收／通过；重新提交更新依据，保留旧记录。恢复设计历史不回滚开发进度，来源差异会重新提示。词、语法的“待设计”提醒和句子的“待设计”处理方式不等同开发进度。

旧的“已确认／待确认／当前实现”不再是主要界面的可编辑状态；原值保留在来源记录中，不能自动转换为完成或验收通过。原句子标注、语法条件和稳定编号均保留。浏览器前进／返回支持页面、语法展开和句子详情路径；所有可能性仍是独立的全局筛选入口。

通用行为只写一次。例如自由移动默认逻辑与玩家实体例外放在语法里；红色化镜框、天平落点等对象细节写在具体句子中。单句可以选择继承、补充、替代、禁止或待定。多个语法同时匹配且默认逻辑不同会提示重叠，不自动选一个覆盖其余定义。自然语言条件供人阅读判断，不在工具里执行游戏效果。

## 编号与笔记保留

- 语法为 `G-0001`，句子为 `S-0001`，句间关系为 `R-0001`。新增词、词义、词性、语法和关系在编辑阶段仅有临时草稿标识；成功保存时才分配正式 ID。保存失败、未保存即删除均不占编号、不留下删除记录。已保存记录的移除采用归档，在下一次保存后进入历史；正式编号不重排、不回收。
- 句子身份由有序的词义 ID 确定。相同符号的不同词义分别编号；同一词义序列匹配多个语法时共享一个句子编号，列出所有来源。
- 修改图片、文字或排序不换编号。移除词义／停用语法后，不再匹配的句子进入“已退役”；编号、笔记和关系保留。重新恢复相同词义与结构时复用原编号。
- 笔记与计算结果分开保存。重新展开只更新匹配结果，不覆盖人工文字。相关词义、语法或句间关系变化后，已有审核记录显示“需复核”；无关编辑不触发复核。
- 恢复历史版本也不会回收后来分配的编号。新版才添加的词、语法等保留为归档数据，可再恢复。

“展开成立”只表示匹配当前语法结构，不代表效果已实现、对象一定支持或没有冲突。没有标注也不表示禁止。自动检查覆盖结构重叠、引用及复核依赖；不会凭长篇自然语言自动证明所有语义矛盾。

## 保存、历史与计算

编辑时浏览器保存本地草稿；点击“保存并更新”后才写入项目，并更新展开结果。重新打开页面可恢复草稿。跨窗口或外部修改导致版本不同，服务器拒绝覆盖旧版本；先导出草稿，再载入最新项目内容。

每个成功保存的版本保留在 `.history/`，可查看变更、对比全文、导出或恢复。历史不会自动清理；更换符号也保留原图片，确保历史可读。备份时一起保留 `design.json`、`.history/` 和 `symbols/`。JSON／Markdown 导出可携带当前尚未保存的编辑，但图片文件需随项目备份。

“历史与版本”分为“保存历史”和“命名版本”。后者由用户主动建立，填写名称及版本说明，固定引用当时已保存的完整设计；普通保存不会自动新增命名版本。支持版本间／与当前编辑比较、导出、恢复。恢复仍保留后来分配的编号和开发进度。导出用于文件备份或交接，不能代替工作台内的版本记录。建立命名版本前必须先保存编辑；版本元数据保存在 `.history/releases.json`。

2026-10-08 按用户要求清理正式使用前的试用历史，以当前已保存设计建立“试用整理起点”。保留用户当前内容和全部编号；此前试用快照已删除，之后的历史不自动清理。

历史默认以“保存前 → 保存后”展示该次修改，用中文字段逐项对比；“与当前编辑比较”则独立计算所选快照与当前内容的全部差异。单句历史包含相关语法、词义及句间关系变化。初始快照没有更早版本，另提供完整原始数据与 JSON 导出。成功写入的新内容按保存事件记录，即使内容改回曾经的版本，也保留这次保存的时间与前一版本；完全没有内容变化的保存不新增事件。旧历史按已有快照时间衔接并标明，不声称能重建旧系统未记录的重复保存。未保存输入不属于版本历史。

组合按语法缓存。只改备注、实现描述或图片不会重新枚举词义组合；增加词义、改变词性或结构时，重新计算受影响的语法，再更新句子索引和复核状态。列表分页显示，语法内先显示最多 60 条，可进入筛选视图浏览全部。每条语法支持 1–8 个槽位；单语法原始组合积、所有启用语法的展开总量上限均为 100,000，超限明确报错，保留原文件，不截断保存。它不枚举任意长词串、所有多句排列或世界状态。

## 初始内容与 SO 对照

当前以实际 V3 `OpeningCatalog.asset` 为来源：11 个词、48 条已登记规则，导入对应符号与 GUID。9 条可编辑语法初始展开 126 个句子。已登记数量只说明引擎当前数据，不代表设计的完整边界。

已有项目设计中的具体行为附有来源；广义语法适用范围标为草案。“已确认／当前实现／草案”分别保留，不能将导入或生成结果视为用户已逐条确认。玩家本人和本质化是同一符号的两个独立词义，未将本质化改称抽象的“变换”。

每个词记录来源 SO 的路径、GUID、原始词 ID 和词义代码。词库的 SO 对照子页显示相对导入基线的设计修改。刷新来源只更新只读快照，不覆盖人工设计。以后用户另行授权更新 SO 时，代理依据这些差异进行映射；中文含义和程序内部英文代码分别维护，词性不会自动转换为某个运行时枚举。

## 后续开发的读取约定

涉及 V3 词义、语法或具体效果的任务，从项目文档入口读取本说明和 `design.json`，对照 `GameDesign.md` 当前设计。用户当次明确指令优先。只处理本次授权范围；工具保存本身不构成实现游戏的授权。

按编号读取所需内容，无需每次通读全部句子：

```powershell
node Assets/Docs/ProjectHelper/inspect.mjs S-0001 S-0068 G-0001
node Assets/Docs/ProjectHelper/inspect.mjs
node Assets/Docs/ProjectHelper/inspect.mjs D-0001
```

无参数列出开发事项；D 编号读取需求、处理记录、提交时设计与当前设计差异。S／G 编号返回词义与来源、匹配语法、默认逻辑、条件例外、单句笔记和相关句间关系，并计算复核状态。实现前检查是否待设计、需复核或存在多语法重叠；旧 `status` 只提供历史背景。关系涉及的其他句子应继续按编号查询。缺失的对象行为不能从句法匹配或 SO 登记情况推断。用户可以直接说“处理 D-0001”或“检查 S-0042 与 S-0087 的冲突”。

## 文件与验证

- `design.json`：唯一人工设计源，包含稳定 ID、词库、语法、句子笔记与关系。
- `catalog.snapshot.json`：Unity 来源快照；`symbols/`：不可变的符号副本／上传图片。
- `engine.mjs`：验证、增量组合缓存、编号与依赖复核；`server.mjs`：本机服务、原子保存、版本检查和历史。
- `app.mjs`、`index.html`、`styles.css`：编辑界面；`importer.mjs`：项目专用只读导入器；`seed.mjs`：初始数据和测试基线，不能代替用户的最新设计。

不需要安装依赖或启动 Unity。命令行启动为 `node Assets/Docs/ProjectHelper/server.mjs`；可用 `PUZZLEAPPLE_WORKBENCH_PORT` 改端口。关掉浏览器不会停止后台服务。

运行 `node --test Assets/Docs/ProjectHelper/workbench.test.mjs`。20 项自动检查覆盖组合、稳定编号、缓存、保存／历史恢复、开发事项、历史字段差异、单句关联设计、草稿移除与正式编号，以及命名版本的快照保留和并发保护。浏览器已在临时数据副本验证新增后删除不产生历史、保存才分配编号，以及命名版本建立和比较。原生拖拽尚未完成端到端验证，可使用点选和排序按钮。本工具不操作 Unity；它可以同时运行，仅可能因文档保存触发资源刷新。
