## 0. 为什么要做

现在组句是拼起来就立即生效。问题：
- **前缀句提前生效**：想拼 `light move floor`，拼到 `light move` 时它已经成立，先播一遍 `light move` 的过场，很烦。
- **抓时机困难**：维特鲁威人房间的方形镜子要在正确时刻停下 `mirror move`，靠拆词不够快、不够准。

句号机制：词拼好只是「草稿」；把句号拖到句尾，句子才算「说完」，这时才判定、生效、播过场。

## 1. 已定设计【已定】

1. 在面板里拼词**不再立即生效**。
2. 一个**英文句号「.」**常驻在面板**右下角附近**（不居中），**稍大一些**，但风格和词一致，**不能看起来像系统按钮**。
3. **只有把句号拖到句尾**才触发判定、效果和过场。**没有点击虚影**（不做「点一下自动落上去」，否则玩家就不需要拖了）。
4. 句子成立（拼对了）时，角落的句号循环泛淡涟漪，提示「可以说完了」。
5. **把句号拖回角落 = 暂停**：持续句停在当前进度，词留着不动；再把句号拖回句子上就继续。
6. **从生效中的句子里拿走任意一个词**：句号自动弹回角落，效果停止（和现在的拆句一样）。
7. **一次性句完成后**：词照旧自动回词库，句号也一起回角落。
8. **首次引导**：玩家第一次拼出成立的句子时（Intro 开局的 `on world`／`off world`），一个**半透明的句号分身**带着**尾迹**，配合角落句号的**缩放 + 涟漪**，从角落滑到句尾，**循环播放，直到玩家真正把句号拖上去**。成功后**永久关闭**这个引导，之后仍保留语法成立时的循环涟漪。
9. 需要检查对现有组句逻辑、前缀句提前生效、观察授予的例句和检查脚本的影响（§6）。

## 2. 概念与状态【建议】

### 2.1 句子的三种状态
| 状态 | 条件 | 表现 |
|---|---|---|
| 草稿 | 词组未被识别，或被识别但没有句号 | 低透明度显示（同冲突句），不生效、无过场。放下句号才为未识别组合划线；被识别时角落句号循环泛涟漪（§4.2） |
| 已说出 | 被识别 + 有句号 + 无冲突 | 生效，和现在的「成立」完全一样 |
| 已说出但冲突 | 被识别 + 有句号 + 与先说出的句子冲突 | 和现在的冲突句一样：不生效、冲突脉冲；先说出的句子拆掉后接管 |

拼不通的草稿在放上句号之前保持无划痕。放上句号后保留完整的带句号句子，划线覆盖整句宽度并记录本次失败。拿走句号或编辑该词组后清除旧划线，等待下一次判定。

### 2.2 数据改动（`CognitionState`）
- `Group` 新增 `Spoken`（bool）：句尾是否有句号。
- 新增总开关 `RequirePeriod`（由 V5Interface／CognitionBoard 上的配置字段注入，**不要用静态可变状态**，P5 关了 Domain Reload）。
  - 关：`Spoken` 视为永远为真，行为与现在一致。
  - 开：`Effective => Recognized && !Conflicted && Spoken`。
- **冲突计算只在已说出的句子之间进行**。草稿不占通道，不会挡住别的句子，也不会被别的句子判为冲突。
- **`Established`（成立时刻）改为在放上句号时赋值**。作用范围按现有规则在「成立」时锁定，所以范围是放句号那一刻的范围。
  - 拖走句号再放回（暂停后继续）时作用范围和运动方向均按 §2.3 保留。
- 新增两个操作：`Speak(groupId)`（放句号）、`Unsay(groupId)`（拿走句号）。
- 任何改变已说出句子词序或词数的操作（`Join`、`Detach`、`Swap`、`ReturnToLibrary`）都会先把该句的 `Spoken` 清掉（句号弹回角落），再按现有逻辑处理。这满足已定第 6 条，也意味着：往已说出的 `light move` 后面接 `floor`，句号先弹回，玩家要对 `light move floor` 重新放句号。
- 新增 `CognitionChange.Speak`、`CognitionChange.Unsay` 两种变更（或复用：`Unsay` 走 `Split` 的语义，`Speak` 走 `Join` 的语义）。**关键**：`Unsay` 必须和现在的拆句走同一条「停止效果、保留当前值」的路径（`SentenceRuntime.Refresh` 里 `kind==Split` 直接 Commit，不播过场）。

### 2.3 运动的暂停与继续【已定：全局统一按方案 A】
用户 2026-11-17 定：**所有「停下」都是暂停，再成立时接着走**。这条是全局规则，不只针对句号机制。
- 三种停下等效：拆句（拿走词）、拿走句号、`no move` 冻结。
- 再成立（重新拼回、放回句号、解除 `no move`）时：
  - **方向**：每个物体沿用自己停下时的运动方向（反弹后的方向也保留）。
  - **相位**：往复、摆动、旋转类运动（门的来回、方形镜摆动、画灯上下摆、球绕肚脐转）从停下时的角度／相位接着走，不从头开始、不跳变。
  - **进度**：一次性定向移动（A move B）从当前位置继续朝目标走。
  - **作用范围**：沿用停下前锁定的范围。拿走句号再放回是同一句，直接沿用。拆词后重新拼出同一规则时，若玩家仍在原范围内的任一空间里，沿用原范围；玩家已经离开原范围，按此刻重新锁定（避免在别的房间拼句却去动看不见的旧房间）。
- **随机只发生在第一次开始**：物体从未被移动过时才随机初始方向；之后只有反弹、落地等物理事件会改变方向。
- 跨章节清空句子：持续效果停止，回访时按各对象自己的复位规则（例如入口镜复位）。
- 现有不符合这条规则的行为由批次 M 修复（见 [00-执行计划.md](00-执行计划.md)）。句号机制直接按这条实现。

### 2.4 运行时（`SentenceRuntime`）
- 现有逻辑只看 `g.Effective`，加入 `Spoken` 后大部分自动正确：草稿不在 `groups` 里，不会进 `added`，不会播过场。
- `Present` 只会在放句号时被触发，所以过场只播最终那一句，前缀问题自然消失。
- `Retire`（一次性句完成后淡出、归库）：归库时句号随句子消失，角落的句号保持原样（句号在角落是无限的，§3.1）。
- `entry.InterruptRemovedWorldSentence()`：拿走 `on world`／`off world` 的句号，等同于现在拆掉这两句（中断盒子展开／退出流程，停在当前姿态）。
- `SentenceFeedback`：带星／弱涟漪在**放句号时**判断和播放，规则不变（有可见变化带星，否则弱涟漪）。持续句循环泛星照旧。
- `SentenceHistory`：只在放句号时记录（一次「说出」算一次尝试）；把句号放在未识别词组上也记录为一次「不成立」。草稿阶段的拼拼凑凑不进历史。（已定）

## 3. 交互【建议】

### 3.1 角落的句号
- 位置：组句区右下角，留出与词间距相同的边距，不压住词库或快照区。
- 大小：比词的高度略大，约 1.3 倍字高的点。笔画颜色、透明度、粉笔质感和词一致（用现有 `SymbolUI`／`CenteredSymbolImage` 的渲染方式，做一个句号符号贴图）。不加底框、不加按钮背景。
- 句号是**无限的**：从角落拖出一个，角落立即还有一个。每个已说出的句子句尾显示自己的句号。
- 拖拽：开场淡入时就能从角落拖动，空面板也能拿起。默认抓取区为 64 × 64 个画布单位，句尾吸附半径为 60。按下后移动即可拖动，拖动中显示和词一样的拖拽图形。悬停在某个词组句尾附近时，沿用现有吸附提示（`snapHint`）指示落点。
- 松手：
  - 在某个词组句尾的吸附范围内 → `Speak`。
  - 其他任何地方（包括面板外）→ 句号消失，回到角落，无效果。

### 3.2 拿走句号
- 拖动某个句子句尾的句号，离开吸附范围松手（拖回角落或拖到任意空白处）→ `Unsay`，暂停。
- 拖整句（拖句首手柄）时句号跟着句子一起移动，句子仍是已说出状态，不暂停。
- 句号不能放在句中间，也不能单独留在组句区里。

### 3.3 与世界拖拽的关系
- 把**词**拖出面板（开阔地、维特鲁威人房间的拖拽实例化）不受影响，词照旧归库并触发世界交互。
- 句号拖出面板：没有世界交互，只是回到角落。

### 3.4 方形谜题的用法
玩家拼好 `mirror move.`，看着镜子摆，在接近 45° 时把句号拖走 → `Unsay` → 镜子停下 → 若在 ±3° 内吸附。拖走句号比拆词快且准，这是这个机制要解决的问题之一。

## 4. 视觉【建议，须与现有风格一致】

整体原则：只用现有的视觉元素（粉笔色的词、双圈涟漪、星芒、淡入淡出），不新增颜色和 UI 框。

### 4.1 句尾的句号
- 和角落的句号同一个符号，大小缩到与词相称（约 1.0 倍字高的点），用正圆，单独占一个正常词宽的格子，以普通词间距接在句尾，圆点左边缘位于格子最左侧，底边与句中符号的实际可见底边对齐。
- 放上去的瞬间：句号从拖拽大小缩到句尾大小（0.15 秒），然后照现有规则在整句上播生效反馈（带星或弱涟漪）。

### 4.2 「可以说完了」提示
- 时机：某个词组从「未识别」变为「被识别」（草稿状态下拼对了）。
- 表现：角落的句号亮度提升并轻微放大到 1.1 倍再回落，约 0.88 秒，同时以句号为中心放一圈**很淡的单圈涟漪**（句号使用圆形涟漪，词组使用 `SentenceFeedback` 的无星弱涟漪）。
- 草稿语法成立时角落句号循环提示。句子本身只在放下句号后反馈，冲突或没有实际作用时仅一轮弱涟漪。拖拽中的句号有跟随圆点的涟漪。
- 多个已识别草稿共用角落句号的提示循环。

### 4.3 首次引导
- 触发：本次运行中**第一次**有词组在草稿状态下被识别，且还从未成功放过句号。Intro 开局通常是 `on world`。
- 表现（循环，每轮约 2.2 秒）：
  1. 角落的真句号放大到 1.25 倍并放出一圈涟漪（0.4 秒）。
  2. 一个**半透明（约 35%）的句号分身**从角落出发，沿一条轻微上拱的弧线滑到该句句尾（0.9 秒，缓入缓出），身后拖一条渐隐的细尾迹（和词飞入词库的轨迹风格一致；没有现成的就用 6–8 个渐隐的残影）。
  3. 分身在句尾停 0.3 秒并淡出，句尾吸附提示同时淡淡亮一下。
  4. 停顿 0.6 秒，重复。
- **真句号始终留在角落不动**，玩家能分清要拖的是哪个。
- 结束：玩家真正把句号放到任意被识别的句子上（`Speak` 成功）→ 引导立即停止，并**永久关闭**。
- 中途：玩家拆掉这句、句子不再被识别 → 暂停引导；再次出现被识别的草稿时继续。面板关闭时暂停，打开后继续。
- 「永久」= 本次运行内（工程没有存档）。重新启动游戏后会再教一次（已定）。

### 4.4 草稿状态的句子外观
- **草稿用低透明度显示【已定】**，透明度与冲突句一致（`CognitionBoard.ConflictAlpha`，当前 0.16），放上句号后恢复为 1。

## 5. 特殊句子与流程【建议】

| 情况 | 处理 |
|---|---|
| 观察授予的例句（`light move`，`ChamberLight` 调用 `TryAcquireSentence` + `PlaceAcquiredSentence`） | **授予时自带句号**（已定）（世界「说出」的例句），保持现在「接管预设运动 + 打开面板 + 播一次成立反馈」的流程不变。玩家想停，拖走句号即可。这也让依赖 `TryAcquireSentence` 的检查脚本不受影响。 |
| `on world`／`off world`（WorldFlow） | 需要句号。首次引导就在这里发生。退出确认流程（`ConfirmingExit`）期间照现有规则。 |
| 一次性句（`on／off light`、`on／off door`、`A move B`） | 放句号才执行；完成后整句连同句号归库。执行中拖走句号 = 现在的拆句（停在当前进度）。 |
| 冲突句 | 有句号但不生效，冲突脉冲；先说出的句子拿走句号或被拆后，它接管（沿用 `pendingTakeovers`）。 |
| `no move` | 同普通持续句。 |
| 跨章节清空组句区 | 句子和句尾句号一起清掉；角落句号不受影响。 |
| 右键长按恢复（拖拽实例化） | 不受影响。 |
| 面板关闭 | 已说出的句子继续生效；草稿保持草稿。 |

## 6. 影响检查（实现前后都要逐条核对）

| 方面 | 影响 | 处理 |
|---|---|---|
| 现有组句逻辑 | `Join`／`Detach`／`Swap`／`ReturnToLibrary` 需在开关打开时先清 `Spoken`；`Commit` 的冲突计算只看已说出的句子；`Established` 赋值时机改到放句号 | 全部包在 `RequirePeriod` 判断里，开关关闭时走原路径 |
| 前缀句提前生效（`light move` → `light move floor`） | 草稿不生效，自然解决 | 验收专门测这一条 |
| 已说出句子再加词 | 句号弹回，需重新放 | 已定第 6 条的推论；验收测 |
| 观察授予例句 | 自带句号，流程不变 | 已定 |
| 作用范围锁定 | 改为放句号时锁定 | 与 SentenceScopeChecks 对照 |
| SentenceHistory | 只在放句号时记录 | 已定；SentenceHistoryChecks 在开关打开时需更新断言 |
| SentenceFeedback | 在放句号时判断 | 无需改判断逻辑，只改触发时机 |
| WorldEntry 的 on／off world 流程 | 放句号才开始；拿走句号 = 中断 | 用 `InterruptRemovedWorldSentence` 现有路径 |
| 镜头演出 `SentencePresentation` | 只在放句号时触发 | 不改 |
| 拖拽实例化 | 词拖出面板不变；句号拖出面板只是回到角落 | WorldDropChecks 不变 |
| 维特鲁威人房间、mirror 虚影 | 草稿状态下的 mirror 句显示虚影（见 mirror 规则 §5.2） | 依赖本机制的「草稿」状态 |
| 检查脚本 | 大量检查直接调用 `State.Join`／`TryAcquireSentence` 并期望立即生效 | 见 §6.1 |

### 6.1 检查脚本策略
- 现有全部检查**在开关关闭时**照常运行，必须全部通过（证明关掉开关 = 原样）。
- 新增测试辅助方法 `Say(state, words...)`：拼词后若开关打开就自动 `Speak`。把依赖「拼完就生效」的检查改为调用它，然后在**开关打开时**再完整跑一遍，确认机制打开后其他功能不坏。
- `TryAcquireSentence` 自带句号，用它造句的 `OutdoorChecks.Grammar` 不需要改。
- 新增 `PeriodChecks` 覆盖 §7。
