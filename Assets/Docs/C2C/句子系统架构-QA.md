# V5 句子系统架构 · 重构前问答

2026-11-20 · 配合[架构草案](句子系统架构.md)阅读。就本轮讨论，可以开始实体登记与范围查询的重构。以下问答记录已确认的玩家行为，末节单列当前代码情况与迁移建议。

## 已确认的玩家行为

**Q1　一次性命令执行途中，玩家又造了一盏灯，新灯参加吗？**

这一轮只作用于下令时的范围，之后生成的物体不参加。例如先说出 `light move door`，再生成的新灯不参加这次向门聚集。即使玩家恰好能在过场期间完成操作，结果也一样。持续句则随当前范围和物体性质更新，例如 `light move` 持续生效时，在范围内新造的亮灯也会移动。

**Q2　先说 `light floor`，再说 `light move`，地面怎么动？**

`light floor` 让范围内的地面发光，因而也成为 `light move` 的对象。每块地面沿用自身的 `floor move` 规则。

| 地面 | 预期表现 |
| --- | --- |
| Intro 第二段通道的移动平台 | 沿轨道往返，照常载人。 |
| 开阔地的地面 | 语义上是地面移动，画面用天空和云的运动来表现。 |
| 位置固定的普通地面 | 保持原位。 |

开阔地还有两个已有的定向句。`floor move light` 和 `floor move door` 会让地面实际托着玩家升向灯或门的高度，拆句后停在当前高度。这两个操作继续保留。

**Q3　“一句话只在部分物体上生效”，玩家会看到什么？**

以 Intro 第一段星光通道尽头、通往运动教学房的铰链白门为例。范围里还有一盏亮灯。先用 `light door` 点亮白门，再说 `light move`，灯开始漂移，白门像收到 `door move` 一样绕铰链往复摆动。此时说出 `on door`，白门先执行开门动作，灯继续漂。开门完成时，若白门仍发光且 `light move` 仍生效，门恢复摆动。白门暂时让开门动作优先，只影响这扇门。

**Q4　门没开时，怎样区分“句子有效但无法执行”和“句子冲突”？**

| 玩家说出 `on door` 时的情况 | 预期反馈 |
| --- | --- |
| 唯一的目标是充能不足的门，或唯一的门已经全开 | 句子语法有效，这次没有可执行的变化，给无星弱涟漪。 |
| `off door` 正在执行，此时又说 `on door` | 开、关指令互斥。后说的 `on door` 进入冲突状态并变淡，正在执行的关门动作继续。 |
| 范围内有多扇门，充能门未满，但另一扇门可以打开 | 能开的门执行。句子有可见变化，给带星反馈。 |
