# 项目上下文

## 已确认
- 项目名称：PuzzleApple。
- Unity 版本：6000.3.9f1。
- 用户希望通过项目文档减少重复解释，帮助后续工作保持宏观设计方向和上下文一致。
- 协作约定与文件归类规则见项目根目录 `AGENTS.md`。

## 设计信息
核心玩法已明确为第一人称 3D 探索解谜：在世界中收集词汇，在 Tab 认知面板中拖拽成句，以认知改变世界状态与交互。物体同时受认知与解谜进度影响，破句不能简单回退所有结果。详细规则、围绕 “The Answer is Within the Apple.” 的三条解法草案、符号语言方向与占位素材策略见 [游戏设计](GameDesign.md)。当前先制作 SacredSpaceV2 中的认知框架、临时输入工具和苹果首次句子收集；完整解谜路线尚未实现。

已确认面板要求：Tab 切换展开/收起；从左向右滑出，贴左全高、覆盖约 1/3 画面，右侧画面不缩放。认知内容使用深色底和用户提供的粉笔字体。展开时禁止行走，行走中打开须短暂减速停下；鼠标可自由移到右侧，但不允许交互场景物品。视角不随鼠标移动，改为自动带随机性的轻微左右 idle 观察。首次苹果句子收集完成后自动打开面板；后续收集是否都自动打开待讨论。

面板初始实现参数（可调，并非固定设计）：滑动 0.25 秒、减速 0.2 秒、yaw ±2.5°、pitch ±0.35°。按用户最新反馈，idle 改为连续低频 yaw/pitch 波形叠加，每次打开随机相位，2 秒平滑进入；不再分段停顿或随机选取转头目标。不添加 roll 或相机位移，保持水平；收起时沿用当前 yaw/pitch，避免鼠标接管后跳回。此版是再次手感试调，尚待反馈；用户表示若仍不自然可先暂用。

idle 参考：[Motion 待机相机](https://docs.motionco.re/components/motion-breathing-component)、[相机曲线调节](https://docs.motionco.re/guides/camera-curves)。借鉴将强度、播放节奏与平滑度分开调节的方法；上述角度、速度、停留时间为本项目试调值，不是参考资料规定值。

美术方向已选择 SacredSpaceV2。用户已确认删除全部旧方案；当前只保留 V2 场景，PC/Mobile 管线与相机统一使用唯一的 V2 renderer（index 0），构建入口同步为 V2。

用户约定：收到 `【模型有重新导入】` 时，主动检查材质/颜色、描边、碰撞、门洞通行、出生位置及派生网格是否同步，并修复相关问题。

颜色要求：仅地毯红色，其余地面白色，墙体保持明亮。当前模型已区分地毯与普通地面。

当前入口已改名为 `TutorialLevel`，仍使用 SacredSpaceV2 的建筑和画面资源。开场已接入镜子凝视获取 I、首次面板、回正镜头与走廊学习走路；学步走到约一半时边走边获得 move，不再低头或停步取词，完整确认流程见 [游戏设计](GameDesign.md)。

基础原型保留 WASD 第一人称移动、鼠标视角、建筑碰撞与走廊出生点；正常移动速度恢复 3.5，开场先锁移动，以约26%基础步速（0.91，叠加起步推力渐入及脚步迟疑）迈出短步，前15%路段维持较慢节奏，之后按距离逐渐恢复；学习期间伴有逐渐减弱的步速顿挫、轻微左右转头和上下起伏，行走路线不被系统偏转，未添加跳跃或冲刺。具体视觉资源和空间参数见 [当前画面方案](VisualDirections.md)。

2026-09-24 更新：已接入 TutorialLevel 的吃苹果路线。首次苹果句子为不成立的 `I no consume apple`；`I consume apple` 允许取到嘴边咬一口并轻抛落地。钥匙留在咬口，交互后获得 `open`，没有道具获取或自动开面板；`I open` 允许交互打开占位门。破句撤销尚未执行的交互许可，吃过/已开门结果保留。`apple move` 改为随机方向飘动。详细设计与资源替换入口见 GameDesign、VisualDirections。

当前认知面板已转入正式流程：无测试输入、信号下拉、加词按钮、任意句式注册、标题或拖拽说明。首次I以字形中心居中漂浮，仍可拖拽；词汇仅由实际交互来源发放。门和门框颜色已由用户自行调整，以当前用户资源为准。
