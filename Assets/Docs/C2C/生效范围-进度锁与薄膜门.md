# C2C｜句子生效范围新规则：整章默认 + 进度锁 + 薄膜门

> Claude → Codex（Astra）实操文档。日期 2026-11-18。
> 本文记录空间与进度的有效规则。命令执行途中的对象加入与空间上限见[架构问答](句子系统架构-QA.md#命令范围策略)。

## 0. 为什么改

改动前规则是「所在空间 + 视野方向（半角 60°）+ 距离上限（30 米），成立时锁定」，再加通道侧身回退、Chapter I portal 隔离、拆词重组时判断是否仍在原范围等补丁。用户的判断：规则不够清晰、不够一致，代码层面也难管理。新规则**取代**上述全部内容。

## 1. 新规则【已定】

### 1.1 默认：覆盖整个 chapter
句子生效后，默认作用于玩家**当前所在 chapter 的全部空间**。Intro（P5 室内部分）、开阔地、Chapter I 各算一个 chapter。跨 chapter 仍清空组句区（不变）。

不再有视野方向、距离上限、侧身回退这些判断。范围内所有具备相应属性、满足自身执行条件的对象都受到影响；玩家当前房间或镜头朝向不能把实际作用对象缩减为一个。on／off door 和 door move 同样如此：例如 `off door` 可关闭连通范围内的白门，Intro 的充能门由玩家感应驱动。

### 1.2 限制一：进度锁
- **进度锁由设计者指定**，与它看起来是不是门无关。在场景里用一个组件标记（见 §3.1）。
- 锁**未打开**时，进度上在它之后的**所有空间**都不受句子影响。默认认为玩家还不能经历、影响它们。
- 按**进度**判断，不按空间位置：即使某个空间在物理上紧挨着、甚至就在初始空间正上方，只要进度在某个锁之后，锁开之前都不受影响。
- 与**玩家是否进入过**无关。例：房间 3 入口门首次解锁后，玩家仍站在门前平台、还没进过房间 3，也能控制房间 3 的东西。
- **多个锁逐层并入**：锁 1 打开，锁 1 之后、锁 2 之前的空间并入范围；锁 2 打开，再并入下一层。
- 已经经过的空间（锁前面的）仍然受影响，除非被薄膜门隔开。

### 1.3 限制二：薄膜门
- 薄膜门把**门内空间与外部隔离**：内外不相互控制。
- **进出薄膜门时重新判定一次**所有生效中句子的作用范围。
- Chapter I 的**花房**和**维特鲁威人房间**目前都算薄膜门。
- 薄膜门的入口以后会要求做一个**统一的特殊效果**（用户稍后定，本轮不做）。

### 1.4 mirror 跨薄膜门【待补】
用户已给的原则（先记下，**本轮不写细则、不实现特例**）：
- mirror 出来的副本本质上是**外部物体的复制体，仍属于外部**。例如副本是一盏灯，在外部用 `on light` 之类的句子仍然能影响它，即使副本位于薄膜空间内。
- 玩家在薄膜空间内有生效的句子，与外部带进来的效果冲突时需要重算；这时外部镜像进来的东西可能消失，改由内部另一个光源的镜像生效。
- 具体镜像规则等用户给完相关逻辑再补。实现上只需保证「副本的归属 = 原件的归属」这一点可以表达，不要把副本硬算成所在空间的物体。

## 2. 我的理解与默认处理【建议 + 待确认】

| # | 问题 | 默认 |
|---|---|---|
| R1 | 进出薄膜门「重新判定」具体是什么 | 当前可达范围是「玩家此刻所在的薄膜区域 ∩ 已解锁进度」。玩家走进薄膜门，持续句**改为作用于门内**，开关与定向命令还要受说出时的空间上限约束；门外原先被控制的东西按全局方案 A **暂停**（停在当前进度，方向／相位保留）。走出来时反过来：门外的东西接着走，门内的暂停。 |
| R2 | 句子生效期间某个进度锁被打开 | 锁后那一层**立即并入**，生效中的持续句马上也作用到新并入的空间。一次性灯光命令和门开关命令只处理该次开始时已解锁的空间，不在执行途中追加新进度层；因此显露第一通道的那次 `off light` 不会顺带熄灭刚解锁的通道星辰，打开白门的那次 `on door` 也不会连开新并入范围的房间 3 入口门。解锁后新下达的命令正常覆盖全部已解锁对象。薄膜区域仍随玩家位置重判。 |
| R3 | Intro 里哪些是进度锁 | 第一通道显现 → 白门 → 车库入口 → 车库内门 → 飘灯房入口 → 楼梯充能门。各门保护的空间见 [V5 主档](../V5.md#已确认要求)。 |
| R4 | 锁「打开」的判定 | 第一通道随首房灯光熄灭首次完全显现时解锁（显现阈值为 1）；关灯命令执行中锁定，显现未完成时保持未解锁，不以玩家跨入或调试传送触发。实体门第一次打开到可通行即算解锁。第一通道首次完全显露后，洞口、小道入口与进入通道的小楼梯持续保留，之后 `on light` 不再隐藏入口或撤去楼梯碰撞。实体门再关上也**不重新上锁**（进度不倒退）。 |
| R5 | `light world`、`no move` | 现在作用于全局，保持不变。 |
| R6 | 一次性句的参与对象与目的地 | 按用户澄清，范围内所有符合条件的对象参与，不按当前／最近房间缩减参与对象。`light move door` 等定向句在各空间使用已有的目的地锚点，没有对应锚点的对象不参与；命令等所有有效目标完成后才结束。门的开关同样遍历范围内全部门，充能感应门只作为门光和聚灯的目标。 |
| R7 | 镜头演出转向哪个房间 | 只决定展示点：优先玩家当前受影响空间，其次进度上最近的受影响空间。门开关演出排除已在目标状态或不满足执行条件的门，避免入口门正在关、镜头却对着未充能门；不改变句子实际覆盖范围。 |

R1–R3 已由用户确认（2026-11-18）。R6 按用户本轮澄清统一到全局对象规则；R4、R5、R7 按默认实施。

## 3. 实现【建议】

### 3.1 数据
- `ProgressLock`（组件）：挂在被指定为锁的门／门槛上。字段：`Unlocked`（运行时）、`unlocksSpaces`（锁后这一层包含哪些空间）、`requiresSpaces`（前置层）、引用门对象或 `WallPassage` 以监听「首次打开／显现」。第一通道使用 `PassageRevealProgressLock` 预制体，白门以前者解锁的第一通道为前置层。
- `MembraneDoor`（组件）：挂在薄膜门入口。字段：`inside`（门内空间集合）。玩家穿过触发器时通知 `SentenceRuntime` 重算。
- 空间仍用现有 `PassageJourney.LightSpace` 掩码（室内）及 Chapter I／开阔地的空间标识。每个 chapter 一份「进度层」表：第 0 层（开局可达）、第 1 层（锁 1 后）…… 由锁组件自动汇总。

### 3.2 计算
```
Scope(now) = 玩家当前薄膜区域内的空间
           ∩ (第 0 层 ∪ 所有已解锁锁对应的层)
```
- 不再在成立时锁定范围、不再按 `Established` 存范围。范围随「锁打开」「进出薄膜门」两种事件重算，其他时候不变。
- 空间范围仅决定候选对象，仍须实时满足句子所指属性。`light move` 只控制正在发光的对象，不能因句子覆盖房间就接管其中的暗 cube；房间 3 的明暗运动与拆句规则见 [V5 行为观察与持续句子](../V5.md#行为观察与持续句子)。
- 全局方案 A（暂停 = 保留方向、相位、进度）照旧：范围缩小时，被移出的对象暂停；范围扩大时，新并入的对象从自己的当前状态开始受控。
- 删除：视野半角、距离上限、侧身回退、拆词重组时「是否仍在原范围」的判断，以及 V5.md 第 7 行描述的 Chapter I portal 特例（由薄膜门取代）。

### 3.3 反馈
范围改变时重新判定整条句子的潜在目标和各空间的实际响应。星芒、三档明暗及持续句循环见 [V5 语句反馈](../V5.md#语句反馈)。
