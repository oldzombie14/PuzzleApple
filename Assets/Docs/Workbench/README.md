# V5 开发工作台

双击 [启动工作台.cmd](启动工作台.cmd)，浏览器打开 `http://127.0.0.1:4320`。需要 Node.js 20 或更新版本，启动脚本也会查找 Codex 自带 Node。服务仅监听本机；无需安装前端依赖。不要直接双击 index.html。不使用时双击 [停止工作台.cmd](停止工作台.cmd)，不会停止其他 Node 服务。

## 工作概览与设计

首页提供符号、语法、具体句子三个入口。全局规则分为「设计原则」和「Agent 工作规范」，可直接编辑并保存。设计原则的正文是可编辑的主题摘要；在「查看当前项目文档依据」可打开 V5 主档及专题的对应原文。工作规范包括 Unity 资源目录、命名、协作与收尾要求。开发时间线按最新在前显示摘要，点开查看具体改动、记录人和关联批次。

- 符号用字形与稳定编号标识。含义备注支持多种用法，词类可多选。「词类」管理页支持新建、重命名、归档和恢复，并显示使用处。
- 语法直接拖入词类或固定符号。放在空隙可插入，放在现有卡片上可替换；拖动已有卡片可换序，也可拖入移除区。新语法可以先保存草稿，启用后参与匹配。共同含义、条件、镜头和结束规则写在结构下方；已有适用限制与执行映射在开发配置中。精确词序例外和具体句子的情境继续保留。过大词表下，可用「试组一句」按需核对和收录组合。
- 「关卡与对象」先列大关（CH），打开后才显示该关空间（L）。编号固定，名称可改。在本关拖动卡片手柄或用左右按钮排列空间。每条边界（J）连接两个空间，只登记一次，两端共享门、进度锁和端点标注。薄膜门的另一端是内侧空间。卡片顺序用于文档排版。打开空间可编辑流程、边界、关联对象与所属大关。空间初稿参考当前 V5 主档，对象初始列表来自已知实现的类别摘要，后续可自行补充。Unity 快照用于对照，页面保存写入设计主档。

## 提需、开发与验收

1. 在「开发批次」中新建草稿，填写本批名称和一个或多个要求。可以只写文字，也可以从设计页加入某个批次，或在一项需求中关联多个设计条目。「选择关联设计」会标出与上次提交的条目版本相比改了哪些字段；首次比较采用工作台初始设计。
2. 保存草稿可继续编辑。提交时冻结该批的要求、各关联条目及其依据，生成一条时间线摘要。批次交接可以导出为 Markdown。
3. 开发中可以发布阶段摘要，记录已完成工作和剩余部分。填写实际改动、自测结果后提交验收。已提交的范围需要调整时，使用「修订需求」并重新提交，前次记录保留。
4. 在「批次验收」中按需求逐项给结论。可以只核对本次已试的条目。返工填写反馈，修改后再送验；所有条目通过时该批完成。已核对的原始结果可从时间线查看。
5. 用户标记会话完成时，在首页「归档已完成会话」汇总本次改动、验证和待办。可关联平台批次或独立归档。会话编号或链接可用于防止重复记录。一场会话的普通编辑、保存与聊天均不会自动生成会话条目。

## 给 agent 的入口

从 Unity 项目根目录执行。读取文档可以离线进行。

```powershell
node Assets/Docs/Workbench/agent.mjs rules
node Assets/Docs/Workbench/agent.mjs list
node Assets/Docs/Workbench/agent.mjs batch B-0001
node Assets/Docs/Workbench/agent.mjs design
```

用户标记会话完成后，agent 可通过已运行的本机服务归档。将下面字段写入一个 UTF-8 JSON 文件，再运行 `node Assets/Docs/Workbench/agent.mjs record <文件路径>`。填写实际完成的内容。独立会话省略 `batchId` 即可。

```json
{"action":"session","summary":"本批改动摘要","detail":"具体改动、验证和待办","sessionKey":"会话编号或链接","author":"agent"}
```

记录开发中批次的阶段进展时，使用 `action: "progress"`、`batchId`、`summary`、`detail`。用户在页面上给验收结论。

## 数据与版本

`design.json` 是可编辑主档（schemaVersion 3）。稳定编号维持设计引用；批次使用 B 编号。旧版在读取时迁移，保存时落盘。既有词序限制、设计备注、原事项依据与旧验收快照保留，旧开发事项按原编号关联到迁入的批次。原始 Unity 数据仍在 `implementation.json`。

`.history/` 保存每次项目保存的版本，浏览器可恢复未提交草稿。「版本历史」可以对照或恢复设计。恢复保留当前的开发批次、已发布的时间线和验收历史。项目版本变化时，独立的词类修改可合并保存；刷新后也可恢复这类草稿。同一词类被双方修改时会保留草稿并显示冲突。

## Unity 快照与工具清理

开发者在 Unity 编辑模式通过 Unity MCP 执行：

```csharp
return PuzzleApple.V5.Editor.WorkbenchSnapshot.Export();
```

该方法只读取 Unity 配置和源码，写 `implementation.json`，不进入 Play、不改游戏资产、不保存场景。网页点击「重新读取实现快照」只读取这个已导出的文件；源文件摘要变化时提示过期，不把它当成实时同步。摘要覆盖 V5 运行脚本、GameData 和当前词图；场景、材质等未纳入完整变更检测，涉及这些修改后应主动重导并实际验收。

已移除 37 个 `PuzzleApple`／`Tools/PuzzleApple` 菜单入口。重复的场景导航、历史检查、一次性搭建和试验入口不再占顶层菜单。游戏玩法、资源创建菜单 `Assets/Create/PuzzleApple` 及仍有用的工具方法保留；没有在清理时运行旧版本搭建或烘焙。

| 保留的方法／类别 | 前提及实际作用 |
| --- | --- |
| `SentenceGrammarDiagnostics.BuildRows(catalog)`、`SentenceGrammarChecks.Verify()` | Edit 模式组合与语法检查；原窗口已移除，网页承担编辑和核对。 |
| V5 `*Checks` | 按各自 Edit／Play 前提调用。Play 检查可能操纵本次测试世界。 |
| `MoveMemoryLoopBaker.Bake()` | 写 V5 星群词条记忆图及帧序列配置；美术变化时按需重做。 |
| `DoorMemoryBaker.Bake()` | P5 Play 且白门关闭时拍摄，覆盖 `Textures/V5/DoorMemory.png`。 |
| `SphereMoveMemoryRecorder` | 仍保留教学球记忆图的实际场景录制流程；没有本次移除的菜单入口。 |
| `SentenceRegionSetup` | 设置进度锁与范围、章节入口等，会保存相关预制体或场景；一次性迁移不自动重跑。 |
| `ColorMapTrialWindow.Open()` | 临时画面映射试验，关闭后恢复，不作为正式效果。 |
| `ShaderStudySetup`／`RefinedShaderStudySetup` | `Preview()` 运行试验副本，`Open()` 加载试验场景，`Create()` 创建独立资产；不作为 P5 日常入口。 |

## 验证与维护

```powershell
node --test Assets/Docs/Workbench/workbench.test.mjs
```

测试涵盖语法识别、旧数据迁移、稳定编号、保存冲突、跨设计提需、阶段进展与验收冻结。测试数据写入项目 `Temp/`，不使用正式设计数据。浏览器验证也使用独立测试目录，可通过 `PUZZLE_WORKBENCH_DATA` 指定，端口由 `PUZZLE_WORKBENCH_PORT` 指定。

修改前端后刷新页面；修改 server/model 后重启服务。不要把测试填入的内容复制为正式设计或验收记录。
