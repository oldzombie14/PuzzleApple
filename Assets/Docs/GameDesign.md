# 游戏设计：认知与苹果

本文整理 2026-09-23 用户描述。已确认的玩法方向、暂定流程和技术建议分别标明。当前已开始制作认知交互框架；本轮范围见下文，完整解谜路线仍是草案。

## 当前认知框架验收范围（2026-09-23 已确认）

- 在 SacredSpaceV2 验收基础交互。临时词汇输入框用于添加独立词；临时成句输入框以空格分词，同时登记句式、添加可拆句子并立即生效。信号从预设 `empty` / `apple move` 选择；`empty` 是成立但无世界效果。两个输入工具后续移除。
- 允许重复添加词、多句同时成立。`apple move` 本轮作为持续效果；最后一句支持它的认知失效后停止。具体移动路径为原型表现，不是最终设计。
- 从句中抽出的词不能直接跨句交换或插入：必须先在外面松手成为独立词，下一次拖动才能加入别句。抽词落点与其他组合重叠时，被相斥推开。
- 抽走中间词后不合并左右两段；各自保留连接关系，落单的词成为独立词并恢复漂浮。拖拽预览不提交认知变化，松手后才提交；词块完全拖离原句才拆出。
- 每个非独立组合句首显示一个 ■，不再自动添加句号。直接拖拽 ■ 可移动整个组合；靠近另一组合首尾并松手可合并，中部重叠则相斥。合并后仅保留句首一个 ■。
- 未登记组合划掉；无效组合加词后仍无效补一道划痕，无效转有效时先从右向左擦除旧字与划痕，再从左向右重写。有效转无效及无效换位暂以划痕反馈，具体破句动画仍可调整。
- 苹果靠近并瞄准时显示用户提供的眼睛图标；平时使用临时 X 准星。首次点击获得 `I hate apple`：中央由小放大展示，再收入左下角，随后自动打开 Tab。苹果只收集一次；拆句不撤销收集事实。收集后再次瞄准苹果显示禁止图标；眼睛、禁止图标与 X 准星按视觉重量匹配大小（扁平眼睛使用更大宽度补偿），均按背景明暗逐像素变色。
- 自动打开 Tab 仅确认用于首次句子收集。后续收集是否每次打开仍待讨论；本轮不据此定案整个收集流程。
- 已提供 `Handodle-rg38A.ttf` 与 `viewer.png`，分别归档在 `Assets/Fonts/`、`Assets/UI/Icons/`。认知框架初版不含镜子教学；随后确认制作的开场流程见下文。吃苹果、钥匙及其他解法仍未制作。

## 核心方向（已确认）

- 第一人称 3D 探索解谜游戏，主要解谜核心是通过 Tab 打开的 2D 认知系统。
- 基本循环：在 3D 世界收集词汇、与物体交互 → 在认知面板拖拽词汇、拼凑句子形成认知 → 世界状态和可用交互随认知变化 → 继续探索。
- 物体状态同时受认知与解谜进度影响。每个交互有独立条件和表现，既有逐例设计，也允许 move 系列这样的共通规则。
- 解谜允许多解。测试章节核心句为 **“The Answer is Within the Apple.”**，目标是打开中央苹果台座后方的门。
- 当前英文只是表达设计的工作语言。未来可能改成独立符号语言，参考《巴别塔圣歌》的负数／否定处理思路，以更简洁的结构表达含义；例如 eat、drink 统一为 consume。尚未决定最终词表与语法。

## 3D 探索与交互（已确认）

| 悬停对象的当前情况 | 光标 |
| --- | --- |
| 可收集词汇／句子的物体 | 眼睛 |
| 当前可交互的物体 | 问号 |
| 潜在可交互，但当前条件不满足 | 禁止符号 |

光标素材由用户提供，不自行绘制。同一物体同时满足多个类别时的显示优先级、普通物体的默认光标尚未指定。

交互是否可用不能只依靠物体类型判断，还要结合当前认知、物体状态和解谜进度。成句与破句都可能改变物体本身或交互状态。

## 2D 认知系统

### 认知的生效方式（已确认）

沿用用户当前的两类称呼，分类依据是触发时机，不是英文动词的语法类别：

| 类别 | 示例 | 生效方式 |
| --- | --- | --- |
| 行为类认知 | `apple move` | 成句后直接生效，3D 世界中的苹果开始移动 |
| 非行为类认知 | `I bite apple` | 成句后还要去交互相关物体，此例为苹果，才触发后续内容 |

`bite` 是说明触发方式的例子，不代表最终词表必须保留它。具体句子的触发类型需要逐条设计，不能仅按是否有动词推断。

### 词汇布局与拖拽（已确认的交互方向）

- 收集的词汇出现在面板内，独立词汇上下轻微漂浮；可在面板范围内拖拽。
- 将词拖到另一词附近时，有轻微吸附并排列在旁边；连接的词不再漂浮。
- 可拖走句中任意词；完全拖出句子后，该词成为独立词并恢复漂浮。如果原句因缺词使其他词成为独立词，它们也恢复漂浮。
- 拖动句中固定词，落点仍在当前句中时，交换两词位置；只有完全拖出去才执行独立判定。
- 不应把“按下并开始拖动”直接等同于最终破句。拖拽过程中的预览与正式状态提交时机尚需后续细化。
- 中间词拆分、跨句拖拽和整句合并规则已按本轮确认补充在上方；吸附距离、长按时间等仍是可调整的手感参数。

### 成立判断与反馈（暂定方案）

语法不成立的处理尚未定案。当前临时方案：不能触发后续交互的句子显示划掉效果。

- 当前不成立，拖入新词后仍不成立：补一道划痕。
- 当前不成立，拖入新词后成立：从右向左擦除，再从左向右重写，重写后无划痕。
- 成句后允许再次破句，必须同步更新相关状态；不能简单恢复成句前的快照，因为期间交互可能已经推进解谜。
- 成立后又变为不成立时的具体动画、移除或换位导致无效时是否补划痕，尚未指定。

“不能触发后续交互”目前是设计描述，尚需区分：未定义的句式、语义不支持、当前环境不满足、已经完成的交互，以及直接生效但不需要点击的认知。不能提前将它们统一判为语法错误。

### 视觉与面板衔接

- 左侧整体表现仍未完全确定，目前偏好黑板与白粉笔字，词汇漂浮、划痕、擦除与重写围绕这一感觉展开。
- 当前原型使用用户提供的 Handodle 字体；眼睛使用用户提供的 viewer.png。
- 已有面板尺寸、滑入方式、停步与 idle 视角约定见 [项目上下文](ProjectContext.md)。认知框架使用深色背景与白色粉笔字。
- 开场教学明确包含“点击右侧 3D 区域退出 Tab”。此时点击用于退出面板，不应据此默认同次点击还会触发物体；首次收集句子后自动打开的 Tab 同样支持点击右侧关闭。当前原型统一支持此操作，关闭当帧不触发世界交互；最终是否推广到整个游戏仍待确认。

## 测试章节流程草案

以下是当前流程，不视为所有细节已经定稿。开场信息是玩家必定获得的部分；三条路线细节可继续调整。

### 开场必经信息（2026-09-23 更新确认）

1. 玩家出生后不可移动，可自由转头。向左连续凝视镜子 2 秒后触发，不需要点击；视线移开重新计时。
2. 短暂锁视角并 zoom in 镜子，获得 `I`。沿用中央放大、飞向左下角的动画，随后自动打开认知面板，`I` 独立漂浮并可拖拽。
3. 按 Tab 或左键点击右侧 3D 区域退出；镜头平滑回正后解锁移动。
4. 移动按向大厅前进的距离逐渐恢复，取最远前进进度：停留不恢复、后退不退化。起步先慢而稳，走出一小段后出现轻微左右视角偏转，再逐渐稳定，表现为学习走路。
5. 学步路线走到约一半时获得一次 `move`，边走边播放中央放大、飞向左下角的收词动画；不低头、不锁移动或视角、不自动打开 Tab。动画开始即发放词汇，之后仍按行走距离逐渐恢复步速，在走廊内、进入大厅前恢复正常。
6. 镜子本轮采用模糊反光材质；玩家模型不制作，黑影可后续添加。旋转幅度、速度曲线和镜头时长是首版试调值，待实际体验反馈。

后续草案：去中央交互苹果，自动收集句子 `I [否定] consume apple`；否定暂写作 `no?`。通过此句确保玩家获得 `consume`。现有苹果仍保留 `I hate apple` 原型，不在本轮替换。

### 解法一：吃苹果取钥匙

- 从初始否定句改成 `I consume apple`，再交互苹果，直接取得苹果内的钥匙，用钥匙开门。
- 当前认知框架原型仍使用 `I hate apple` 测试首次收集（见上文验收范围）；它不代表本节正式流程的初始句，后续接入流程时需同步。本次仅修订设计文档。

### 解法二：苹果血与法阵

1. 去某房间，从画像或雕塑等来源获得“女人”，从桌上获得“酒”。具体来源待定。
2. 组成 `女人 consume 酒`，触发画像特效（可能碎裂），取得 `destroy`。具体表现和是否需点击待定。
3. 回中央，组成 `I destroy apple`，触发玩家把苹果扔进碗里并使其碎裂，碗里留下红色液体。投掷可用预烘焙表现，不要求物理模拟；具体交互触发时机待细化。
4. 交互红色液体取得 `appleblood`，交互旁边画笔取得 `pen`。
5. 用 `pen consume apple blood` 使笔浸血。
6. 用 `pen move` 使笔自动在地上画法阵，然后开门。

`appleblood` 与 `apple blood` 均来自当前描述，是否为一个词汇、最终显示形式尚未统一。各阶段的一次性结果、重复执行与破句后的具体表现待逐条设计。

### 解法三：不存在与等同

1. 另一个房间有天平，一侧有苹果；交互空盘获得“不存在”（暂写 `unexist?`）。
2. 组成 `apple unexist`，使苹果消失，主场景的苹果也消失。
3. 再点击天平，获得 `equal`。
4. 组成 `I equal apple`，被门识别后开门；识别的距离和触发方式未定。
5. 此时可用 `apple no unexist` 让苹果们重新显示。

苹果消失具有跨场景物件的影响；哪些对象共享“苹果”概念、已被吃掉或毁坏的苹果是否参与重新显示，仍需后续明确。

### 非关键效果举例（未穷举，均待逐条设计）

| 认知 | 当前设想 |
| --- | --- |
| `apple move`、`wine move` | 对应物品移动，可提炼共通规则 |
| `I hate woman` | 可能触发一句吐槽 |
| `I consume woman` | 吐槽：“不你不能，想什么呢” |
| `I no hate wine` | 允许交互酒并饮用，随后产生眩晕 shader 效果 |

吐槽可以用画面下侧半透明黑框显示。这些是不卡进度的小效果示例，不是完整支持句式清单，也不意味着现在开始制作。

### 已知设计问题

- 解法引导不足：第一条较直观，第二、三条较晦涩。先按当前方案记录，后续可能改，也可能测试章节暂时保留。
- 三条解法共用苹果，可能互相影响；路线混用、苹果毁坏／消失后的继续解法，以及防止卡关的规则尚未定义。

## 原型素材策略（用户认可的方向）

美术未到位时，可以使用几何体，并直接贴文字标注对象；复杂效果可先用文字描述，例如“画破碎”，临时表示效果已经发生。用户逐步补充正式美术。占位表现仍应反映真实玩法状态，后续替换美术时保留玩法逻辑。

## 数据结构与后续建议

当前已落地：词汇、句式和冲突关系均为 SO 配置，统一由 `Assets/GameData/Cognition/Catalog/TutorialCognition.asset` 显式引用，场景中的 CognitionBoard 引用该目录。`WordDefinition` 保存语义 ID 与显示文字；`CognitionState.Word.Id` 表示面板上的具体实例。按来源记录一次性获取，不限制不同来源发放同义词；只接收已登记词汇，不提供任意创建词汇的运行入口。教学阶段、已咬苹果、已开门和词汇获取记录独立于规则资产；拆句不回退事实。会话状态仍未实现跨会话存档。下表中的通用目标选择、复杂条件和完整事实系统仍是后续扩展建议。

核心原则：**当前认知、持续的解谜事实、物体实例状态和视觉表现分开管理。** 不把破句实现成撤销此前所有效果，也不在每个物体上重复堆叠句子字符串判断。

### 当前 SO 配置方式

- `Assets/GameData/Cognition/Words/`：7 个词汇资产，ID 使用稳定的小写语义标识，显示文字独立编辑。
- `Rules/`：5 条句式资产，记录稳定规则 ID、有序词汇引用与效果。`Conflicts/`：显式效果冲突配对，当前为玩家自动移动与禁行。
- `Catalog/TutorialCognition.asset`：当前启用的词汇、规则和冲突列表。新资产必须加入目录才生效；不靠扫描文件夹或文件名推断规则。新增入口为 Project 窗口 `Create > PuzzleApple > Cognition`。
- 修改配置在下一次 Play 生效；句式与冲突在会话创建时编译为运行查找表，不在拖拽时反复加载资产。规则 ID 与面板实例 ID 分开，多句可共享同一条规则。
- Catalog Inspector 即时列出错误；菜单 `PuzzleApple > Cognition > Validate catalogs` 检查重复 ID／句式、缺失或越界词引用、未知效果、自冲突、无规则支持或重复的冲突配对。运行初始化也验证，错误配置不会静默回退到旧规则。
- 效果枚举是现有世界行为的代码接口：持续移动、漂浮、禁行，或授予吃苹果／开门的交互许可。添加使用已有行为的新句式仅修改 SO；新增全新行为仍需要实现执行代码。当前效果含具体主体（玩家／苹果），尚无任意实例目标选择或复杂条件 DSL。
- 资产不会记录玩家已收词、位置、当前冲突或已开门等会话结果。移动、吃苹果、钥匙与门的执行组件以及 40% 冲突透明度规则保持原实现。

| 数据层 | 建议记录 | 目的 |
| --- | --- | --- |
| 词汇定义 | 稳定语义 ID、显示文字／符号、美术引用 | 将含义与英文显示分离，方便以后更换符号语言 |
| 已收集词汇与面板实例 | 获取记录、面板词实例 ID、位置、所属句子 | 区分“知道这个词”和“面板上的这一个词”；词能否重复使用仍待决定 |
| 句子组合 | 有序词实例、连接关系、拖拽预览、判定结果 | 布局与语义分开，支持换位、拆句与漂浮状态 |
| 认知规则 | 语义模式、适用对象、前提条件、触发类型、效果 | 少量通用规则配合关卡特例，无需一开始建立完整自然语言解析器 |
| 解谜事实 | 获得钥匙、笔已浸血、法阵已完成等记录 | 保存已发生且按设计需要保留的结果，避免破句误清空进度 |
| 世界对象 | 实例 ID、概念／标签、实例自身状态 | 区分多个苹果实例与共同的 apple 概念，支持群体影响和局部变化 |
| 交互与表现 | 可用条件、执行结果、表现引用、重复策略 | 同一套条件驱动光标和实际点击；占位文字可替换成动画或特效 |

建议的状态更新过程：提交词汇组合变化 → 识别当前认知 → 对比新增／失效认知 → 结合现存解谜事实与对象状态重新计算世界和交互可用性。点击交互成功或直接效果完成后，再更新相关事实，并重新计算受影响对象。

持续效果与一次性事件需要区分。例如 `apple move` 可表达“认知有效期间移动”；取钥匙、完成法阵则可能留下持续结果。这里是结构建议，具体哪些结果保留、哪些可重复、破句后如何变化，必须按交互设计确定。不能因刷新状态或重新打开面板而反复执行一次性事件。

规则优先支持明确设计过的语义组合，以及 move 这类可泛化模式；否定作用域保留扩展位置，暂不假定给任意句子加 no 都能得到简单反向效果。句子判定结果宜分别保存“能否识别／是否支持／条件是否满足”，再由最终 UI 规则决定是否划掉。

### 后续制作相关系统前再确认

- 否定的形式与作用范围；最终词汇粒度。
- 后续关卡如何发放重复词。当前允许重复词实例与多句同时成立，每个词实例仅属于一个组合；冲突双方全部失效并降低透明度的规则已确认。
- 成立判定在更复杂环境条件下如何映射视觉反馈；当前支持已登记、未登记、冲突三个判定维度。
- 各规则影响概念下所有物件还是指定实例；一次性、可重复、持续效果的生命周期。
- 各解法混用后的状态与防卡关规则；门的识别、钥匙使用等交互条件。
- 点击 3D 区域关闭面板是否为全局行为；光标状态重叠时的优先级。

以上问题不妨碍本次设计记录，无需现在一次性回答；用户推进到对应内容时再细化。

## 2026-09-24：吃苹果与开门流程（已确认）

- 苹果首次交互改为获取 `I no consume apple`，该句不成立、显示划痕；展示结束自动打开左侧面板，Tab 或右侧点击关闭，关闭点击不穿透。收集后禁止再次收集。
- `I consume apple` 成立时，未吃的苹果显示问号并允许点击；拆句立即禁用。点击后从右侧取到嘴边，咬一口、短暂展示后轻抛至附近地面；吃过的结果不因破句回退。
- 被咬苹果使用用户的 `苹果被咬.fbx`，表皮沿用原材质，咬口为微黄果肉。钥匙使用用户的 `key.fbx`，缩放后斜插进咬口，齿端埋入果肉，圆环柄露出；咬开时立即显露钥匙，并随苹果一起展示、旋转和抛落。玩家需要瞄准并交互钥匙取得一次 `open`，不自动打开面板。钥匙留在世界中，不进入道具系统。
- 门首次交互显示眼睛并发放一次 `door`，不自动打开面板，也不打开门。已收词后，只有 `I open door` 成立时门显示问号并允许点击；`I open` 不成立。拆句立即禁用尚未打开的门，已开门不回退。
- 保留开场取得 `move` 与 `apple move`。后者让未吃的苹果沿随机水平方向持续飘动、轻微上下晃动；漂浮速度为 0.8 米/秒，遇障碍沿表面偏转。最后一条有效 `apple move` 拆开后恢复重力，保留惯性自然落下；重新成立从当前位置起浮并重新选方向。已吃的苹果不再受此句影响。
- 首次苹果句子与 `open` 都按来源去重；认知许可与收集、吃过、已开门等会话事实分开。当前仍无跨 Play 会话存档。
- 本节覆盖上文旧原型 `I hate apple` 和“直接取得钥匙”的描述；其它解法仍为草案。

## 2026-09-24：开场手感修订（已确认）

- 学走路表现采用轻微步速顿挫、左右视角摇晃和上下起伏，不让行走路线自行左右偏移。

## 2026-09-24：走路中获得 move（已确认）

## 2026-09-24：持续行走与苹果抛落

- 已确认：`I move` 可以成句，生效期间强制持续移动；打开 Tab 后沿原来的行进方向继续走。多条有效句叠加，拆掉最后一条后撤销效果。
- 已确认：`I no move` 单独生效时使玩家无法移动，保留转头、面板操作和重力。`I move` 与 `I no move` 同时存在时，双方整句与方块均以原色的 40% 不透明度淡化且不生效，恢复普通 WASD；所有参与冲突的重复句同样处理。拆除其中一方的最后一句后，另一方立即恢复效果。无关句子不受影响；划掉表示句式不成立，降低透明度表示句式成立但认知冲突，解除后恢复原透明度；不改变字体或色相。
- 当前方向实现默认（尚待用户对方向选项反馈）：面板关闭时沿当前水平朝向自动走，可转头改变方向；面板打开时锁定打开前的行进方向，面板的视角晃动和 WASD 不改变它。未开始走动就在面板中成句时，沿打开面板时的朝向起步。碰撞和演出锁仍正常生效。
- 苹果抛落先微微上扬，再按重力加速落下，带小幅持续旋转；触地轻微回弹、晃动后停在倾斜姿态，按实际网格最低点贴地。钥匙在咬开时就已经可见，整个过程随苹果移动。
