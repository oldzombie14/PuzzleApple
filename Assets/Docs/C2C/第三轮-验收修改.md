## 1. 句号：从「拖拽」改为「自动出现 + 点击」（批次 12）

> 仍是试验功能，`Require Period` 总开关保留，关掉时与「拼完即生效」完全一致。本节**取代** [句号生效机制.md](句号生效机制.md) 中关于角落句号、拖拽放置、拖拽引导的内容；暂停／继续、自动弹回、一次性句归库、观察例句自带句号、草稿低透明度、历史只记说出的尝试等规则**保持不变**。

### 1.1 已定【已定】
1. **所有多词组**的句尾都**自动出现句号**，位置和排版与现在放下句号后的位置相同（占一个正常词格）。语法成立与否都出现（已定）；语法不成立的组合，点击句号后整句**划线**（沿用现在放下句号后的划线效果）并记一次失败。
2. 自动出现的句号是**未说出**状态：透明度与草稿句一样低。
3. **平时**：句号在「未说出透明度」到「说出透明度」之间**若隐若现**。
4. **首次引导**：改为**涟漪引导**。第一次出现**语法成立**的句子时，句号循环泛涟漪（用现有句号涟漪），直到玩家第一次点击；之后**永久关闭**涟漪引导（本次运行内），只保留若隐若现。原来「分身带尾迹从角落滑到句尾」的拖拽引导**删除**。
5. **鼠标悬停**在句号上：透明度恢复正常。
6. **点击句号**：停止涟漪，进行成句判定（= 原来的「放下句号」：判定效果、冲突、历史、演出）。
7. **停止已生效的句子**，以下方式均使效果暂停，按全局方案 A 保留进度；各自对词和句号的处理不同：
   - 拆句（拖走词，和现在一样）；
   - **右键消融**：词移除该词，整句手柄移除整句；句号仅消融自身并暂停，保留词；
   - **把句号拖离句子范围后松手**：句号淡出，随后按第 1 条重新出现在句尾（未说出状态）。

### 1.2 细节【建议】
- **若隐若现**：透明度在草稿透明度（`ConflictAlpha` 0.16）和 1 之间做慢速正弦呼吸，**周期约 2.5 秒**（可调）。不缩放、不加涟漪，避免和首次引导混淆。
- **悬停**：0.15 秒内渐变到 1，移开后回到呼吸。悬停时鼠标指针用现有「可交互控件」的白点样式。
- **点击判定**：按下并在句号上松开才算点击；按下后移动超过拖拽阈值就转为拖拽（只对已说出的句号有意义）。
- **点击后**：句号透明度固定为 1，词组透明度恢复，播现有的生效反馈。
- **右键消融【已定】**：单词、草稿和已说出句子均适用。右键词时消融并移除该词，右键整句手柄时消融并移除整句；逻辑立即更新，未移除的词保留。右键句号仅消融句号并暂停，保留全部词；约 0.6 秒消融结束后，句尾恢复草稿句号，可再次点击说出。草稿句号右键也消融后恢复，词保持草稿。句号与词共用现有消融效果，残影不接收输入。世界里的右键回收规则不变。
- **拖走句号**：只有已说出的句子的句号可以拖。草稿的句号不能拖（它只是提示）。
- **删除**：角落常驻句号、从角落拖出句号、句尾吸附放置、拿起句号时跟随指针的圆波、拖拽引导分身。`Punctuation` 设置里对应参数清理掉。

## 2. Intro 修改（批次 9）

### 2.1 星芒加柔光【已定 + 建议】
- 问题：星芒光比较弱，玩家未必联想到它是光源。
- **不额外叠加柔光层**，保持接近未加柔光时的星芒本体表现。
- 范围：白色阶梯黑底段上可收集 light 的白色菱形星芒（`AscentStars`）。通道里的星芒（`CorridorStars`）**一起加，同一套参数**（已定）。
- 做法：星芒保持清晰的白色菱形轮廓、闪烁与本体发光。共享 StarGlowStyle 的 haloOpacity 为 0，附加光晕 Renderer 关闭；自发光保持当前值 1。通道与白色阶梯同步，不叠加圆形或菱形柔光层。
- 参数（强度、光晕半径、透明度）放在 Inspector，截图给用户确认后再定。

### 2.2 拿 3D light 的场景：空气墙与掉落回房间【已定】
- **主方案是空气墙**：白色阶梯两侧和顶端小台四周加不可见碰撞体，玩家不能走下或跳下楼梯边缘。高度要挡住跳跃（建议 3 米）。正常游玩时不应该掉下去。
- **掉落回房间只是兜底**（防止漏洞或调试时意外）：玩家低于楼梯底面一定距离（建议 8 米）时，淡黑 → 回到房间 3、站在充能门前、面朝门 → 淡入。词库、句子、灯的状态都保留。复用充能门「敲晕重生」已有的淡出与重生流程。
- 回到**房间 3 充能门前**（已定）。

### 2.3 房间 2：未学 move 时点亮的暗球也要动【已定】
- 现状：直接进入房间 2、没有收集 move 时，用 `on light` 点亮暗球，暗球不动。
- 规则：未学 move 时房间 2 的示范代表「世界规则是 light move」，**所有具备 light 性质的东西都应该 move**。暗球被点亮后就是 light，应和其他示范灯一起运动；熄灭后暂停（不变）。
- 检查同类情况：房间 2 内任何被点亮、或玩家拖进来的灯，在示范状态下都应跟着示范运动。学会 move 并接管后按现有逻辑。

### 2.4 房间 3（最后的房间）流程调整【已定】
> 2026-11-18 用户补充；本节统一维护房间 3 入口、初见、授句与充能规则。

**已定**
1. 房间 3 **默认黑暗**：飘灯初始熄灭，**只有充能门亮着**。
2. 门的发光效果现在很怪（不亮、还有黑边），改成和其它发光物一致的做法。
3. 充能条**初始已有一点能量**（来自开局就在生效的 `light door`）。
4. 玩家**点击门**，获得例句 `light door`，并自动弹出 Tab 面板，显示这句**持续生效中**的 `light door`。
5. **拆掉 `light door`**：门渐渐不再发光，并且**掉能量**。
6. **满能条件**：门发光（`light door` 生效）**与**所有灯都聚到门边**同时成立**，能量才够充满。
7. 平时灯飘动时，**飘到门边附近也会给门充能**：范围可以稍大，但充得不多，并有一点显示来暗示玩家。
8. **底能**：`light door` 被拆、房里又没有其它亮灯充能时，能量掉到**很低，但保留一丝丝**，暗示「有光源在给它能量、这条充能条是能被充的」。
9. **`light door` 不加速充能**。
10. **`light light` 保留加速**，但表现改：充能条**不再直接变色**，而是在**充满之后**再慢慢渐变一点颜色，只是**微微橙红**，整体饱和度偏低。
11. **房间 3 入口加一扇实体门**，作为进度锁（见下方「房间 3 入口门」）。

**建议实现**
- **门的发光**：门面和门龛内侧使用均匀柔和的自发光，不加黑边，不出现中央亮斑；门前光源照亮周围环境，门面不再叠加反射高光。暗房初见与开灯后均须看清门形、充能条和刻字，避免大面积过曝。门面自发光取 1.5，高于泛光阈值、保持可见柔光；充能条常态发光 1.2；面向门时的局部 Bloom 抑制不再依赖充能量，初见低能量也生效。充能条在门龛左右与顶部外侧留 0.18 米间隔。刻字未充满时加深对比，充满后缓慢发出克制的光，保持笔画可辨。
- **开局状态**：开局时 `light door` 的效果由世界持有（同观察授予前房间 2 的示范），门亮着。首次点击直接打开 Tab，把生效中的 `light door` 交给玩家，不先弹出中央 `door` 收集动画。授句使用 `TryAcquireSentence` + `PlaceAcquiredSentence`（自带句号、已说出），在新句子上播一次成立反馈，效果由句子接管、门的发光不中断。只授予一次；之后门仍按 `door` 收词规则处理，已知时显示已知词反馈。
- **能量构成**（总能量 0–1，按分量叠加，参数可调）：
  - **底能**约 **0.03**：一丝丝，永远不会掉到它以下，充能条上始终能看到一点亮。
  - **门发光**（`light door` 生效）：上限约 **0.4**，按现有充能速度慢慢涨。开局时这部分已经涨到约 0.12，所以开局总能量约 **0.15**。拆句后按现有衰减速度掉回底能。
  - **灯聚到门边**（`light move door` 后停靠在门框外侧的停靠位）：按停靠的灯数比例提供，全部停靠时约 **0.57**。
  - **飘过门边**：未停靠的亮灯飘进门前一个较大的范围（建议门框外 4 米，现有充能半径的 2 倍左右）时，每盏灯给一点少量充能，总量上限约 **0.1**，离开后缓慢衰减。
  - **满能闸门**：只有「`light door` 生效」与「全部亮灯都已停靠」同时成立时，总能量才允许到 1；否则总能量最多停在约 **0.95**，避免飘过的灯凑满。最后一盏灯停靠后仍按充能速度连续补满，解除上限不能让充能条瞬间跳到满格。
  - **`light light`**：生效时充能速度 ×1.5（保留现有倍率，可调），不改变各分量上限。
  - **`light door`**：只提供上面那块能量，不加速。
- **充满后的颜色**：去掉现在 `light light`／`light door` 生效时充能条立刻偏暖的做法。充能条和门上刻字平时用中性白发光。只有在**充满之后**、且 `light light` 生效时，才在约 1.5 秒内慢慢渐变到一点点橙红（建议色相约 20°、饱和度不超过 0.2，明度不变）。拆掉 `light light` 或掉能时再渐变回中性白。`light door` 不带这个变色。
- **飘过门边的提示**：灯进入大范围时，最近那段充能槽微微亮一下并缓慢上涨一点，同时灯与门框之间出现一条很淡的细光丝或门框边沿轻微泛光（取其一，用现有发光材质，透明度很低）。离开后提示淡掉。
- **房间默认黑暗后的玩法**：飘灯熄灭时不能充能也不能被聚集（light 指发光的光源）。玩家需要 `on light` 点亮它们，再 `light move door` 把它们聚到门边，同时保持 `light door`。

**房间 3 入口门【已定 + 建议】**
- **已定**：在第二段通道通往房间 3 的入口做一扇**实体门**，作为**进度锁**。开门方向与白门**相反**，**转轴在右侧**。材质、表现与白门同步。支持 `on door`／`off door`，能被句子控制。相关的镜头演出（cut scene）要一起调整。
- **为什么**：房间 3 原来是敞开的门洞，玩家在房间 2 或通道里就能用句子控制它（新范围规则下它在同一层），带着 `on light` 进来就看不到「全黑、只有门亮」的第一眼。加了这把锁，门开之前房间 3 不受句子影响。
- **外观【建议】**：直接复制白门做镜像。门洞尺寸沿用 3.6×3.8 米。通道一侧是白色门面、白色圆球把手（黑白两档硬边明暗），右侧露出圆柱转轴，门洞保留动态细线边框。房间一侧关门时与房间 3 墙面同材质、同补光，不暴露入口；开门时随进度渐变成通道一侧的白色质感，关门再渐变回去（同白门）。房间 3 默认黑暗，所以房间一侧关门时几乎看不见门，这是对的。
- **控制【建议】**：实现 `ISwitchableDoor`。`on door` 绕右轴向通道缓起缓停地打开 135°（与白门方向镜像），`off door` 原路关回；`door move` 往复；拆句停在当前角度，重组继续；on／off 与往复共存时先完成开关再恢复往复。开门穿过玩家、停下后重叠就等玩家离开再恢复碰撞，关门保留门洞占用保护（同白门）。点击门：已有 door 时显示已知词反馈。
- **门的作用范围【已定】**：统一遵守 [全局范围规则](生效范围-进度锁与薄膜门.md) §1.1、R6，范围内所有满足条件的门都响应，进屋后回头可关闭入口门；镜头选一个展示目标不限制其它门。房间 3 入口门把手使用与房间 2 白门相同的材质和球形描边参数。
- **进度锁**：入口门第一次打开到可通行即解锁，房间 3 并入范围；之后关门不重新上锁。Intro 的锁变为三把：白门 → 房间 3 入口门 → 充能门（见 [生效范围-进度锁与薄膜门.md](生效范围-进度锁与薄膜门.md) R3）。
- **灯光**：门关着时，第二段通道的环境光、雾和 Bloom 不再取房间 3 的补光（看不进去）；开门时随开门进度连续过渡到现有「通道里能看到飘灯房」的状态。§2.6 的亮度路线检查把这扇门的开、关和穿过都加进去。
- **镜头演出调整【建议】**：
  - 在通道里 `on door`：镜头保持原位，平滑转向入口门（同白门开门）。门开后，镜头停在门口看到房间 3 全黑、只有充能门亮的画面再交还控制。
  - 门关着时，在通道或房间 2 里说 `on light`／`light move` 不再转向房间 3，也不在房间 3 播演出。
  - 白闪回访落点「充能门房间侧门前」与楼梯掉落兜底都在锁后，回到房间 3 时入口门已解锁，不受影响。
  - 敲晕重生只涉及充能门，不变。
- **回访与存档**：入口门的开合角度与解锁状态跟随现有门状态保存；从室外白门回来时入口门保持离开时的状态。

门龛几何、停靠、升降、失力下落与重生见 [Intro 收尾 B1–B4](Intro收尾-充能门与白色阶梯.md#批次-b充能门依赖批次-a)；作用范围统一见 [生效范围-进度锁与薄膜门.md](生效范围-进度锁与薄膜门.md)。

### 2.5 收集 3D light：去掉先变暗【已定】
- 现状：点击顶端立体 light 收集后，画面先突然变暗。
- 去掉这个变暗过程，点击后直接进入原有的涟漪 → 白闪 → 回开阔地。排查是哪一步造成的（可能是曝光／环境光被重置，或白闪前有淡黑），修掉即可，不改其余演出。

### 2.6 全局：场景之间的灯光过渡要平滑【已定】
- 现象：在房间 3 回望时会**过曝一下**；进入最后的阶梯时会**亮一下**。
- 要求：注意全局的场景过渡灯光衔接，**不要乱闪，要丝滑地过渡**。
- 做法【建议】：
  - 排查每个会切换曝光、环境光、雾、补光或天空背景的地方，找到瞬间跳变的那一帧（现在多半是在进入某个空间触发器时直接设值，或两个空间的补光同时生效后再关掉一个）。
  - 统一改为按位置或时间插值：跨空间时曝光／环境光／雾在 0.6–1.0 秒内（或按玩家在门洞、通道里的位置）平滑过渡，任何一帧的亮度变化不超过可感知的跳变。
  - 至少核对这些位置：房间 1 ↔ 通道 1 ↔ 白门 ↔ 房间 2 ↔ 通道 2 ↔ 房间 3（双向，包括站在门口回望）、房间 3 → 充能门 → 阶梯起点、阶梯黑白过渡、白闪 → 开阔地、开阔地 ↔ Chapter I、Chapter I 走廊 ↔ 花房／维特鲁威人房间。
  - 写一个检查：沿这些路线以固定速度移动并转身回望，记录每帧画面平均亮度，相邻帧亮度差超过阈值即报错。

### 4.2 建议参数

**画框高度（考虑跳跃）**：去掉阶梯后画框下沿离地约 1.59 米，玩家跳不上去。完全降到地面又不像挂在墙上的画、像一扇门。建议改成「**窗台高度，跳一下能进去**」：
- 画框下沿高度 = 玩家实际能跳到的高度减去余量，即 **`Jump Height − 0.15` 米**（Astra 读 `FirstPersonController` 当前的 Jump Height 来定，例如跳高 0.9 米时下沿约 0.75 米）。这个高度不能直接走上去，但一跳就能越过，和以前花房「从踏步跳过框槛」的手感一致，画框也仍然像挂在墙上。
- 房间地面与画框下沿齐平，房间内不需要台阶；从房间出来时往下跳回走廊。
- 画框、画框后的房间一起下移；中心高度随之降低，保持画框原尺寸。
- 下沿高度做成一个参数，用户试玩后可调；如果用户觉得仍不好看，再考虑贴墙放一块低矮的整块踏板（一级，高度约为下沿的一半）。

**空间太大、走路太慢**【已定范围】：适用于 Chapter I 中**除刚进入时的到达方盒以外的整体**：主走廊、花房、维特鲁威人房间。到达方盒（6 米黑盒）尺寸和其中的移速**保持不变**。
- 加快移动速度：在上述空间内步行速度 ×1.3（按空间配置的倍率，进入方盒内恢复 1.0；不影响 Intro 和开阔地）。倍率切换要平滑，不要一步突变。
- 适当缩小尺寸：建议等比缩到约 0.8。
  - 主走廊：长约 54 → 43 米，宽约 21 → 17 米，高约 22 → 17.6 米。整体缩放 V4 Corridor 模型和墙体，**不要单独压扁某一边**，避免模型互相穿插。
  - 花房：随走廊等比缩放，活画框与房间的相接关系保持。
  - 维特鲁威人房间：在调浅后的基础上同样 ×0.8（约 14.4 × 12.8 × 14.4 米），人物、方形、圆、机关及对称线一起等比缩放，谜题参数中的长度（半径、光路）随之缩放，角度和时间不变。
  - 到达方盒保持 6 米、贴在缩放后走廊的端墙上，入口镜位置随方盒；方盒展开时墙板不能穿出缩小后的走廊。
  - 缩放后重新摆放两个活画框和对面的维特鲁威人原画、展柜与天平、天花灯，并重新校核所有碰撞体（墙、地面、画框槛、方盒、展柜、人物与机关）。
